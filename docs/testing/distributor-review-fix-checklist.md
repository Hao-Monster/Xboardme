## 验证顺序与边界

1. 先新增行为回归并记录原实现失败，再修改源码并运行对应回归。
2. 稳定后运行全部 JavaScript、完整脚本手机尺寸 Chromium、PHPUnit、PHPStan、Composer audit、部署脚本语法、workflow 验证和 `git diff --check`。
3. 所有购买、续费、登录、退出请求均使用本地模拟接口；PHP 使用强制内存 SQLite。
4. 真实手机锁屏/隔夜、真实 BFCache、候选镜像资源身份和上线后验收仍属未执行项目，不能用模拟浏览器通过代替。
5. 保留 `.codex-browser-fixtures/`、admin 子模块和其他原有无关改动；不清理、不混入本轮改动。
