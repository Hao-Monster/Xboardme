# 分销订阅名称测试方案和任务清单

本轮验证旧订阅保持原样、只有新购订阅采用新名称。上线判断必须同时考虑业务正确性、历史数据完整性、访问权限和客户端兼容性；本地测试通过不能替代 MySQL 演练与实际客户端验收。

业务代码基线为 `1e5e7d4af7947c1c65b06e0b93b1c7c27a116a5b`，分支 `develop`。需求规则见 [分销订阅名称说明](distributor-subscription-names.md)，本轮执行证据见 [测试报告](distributor-subscription-names-test-report-20261006.md)。

## 验收范围

1. 已有订单及订阅不回填、不改名。客户端响应仍输出 `订单号：原订单号`，原链接备注和二维码格式保留。
2. 旧订阅续费继续使用旧名称；功能上线后新购订阅使用 `商户名称-YYMMDD-六位短号`，不带“订单号”前缀。
3. 日期为首次购买时的北京时间日期。商户名称最多 16 个 UTF-16 单位，完整名称最多 30 个单位；补充平面字符通常占 2 个单位。
4. 新名称和短号只分配一次，商户改名及续费不改变已有订阅身份。财务订单号、订阅 token、UUID 和设备授权规则保留。
5. 短号公开展示，但不能用于订阅鉴权。唯一约束、碰撞重试与失败回滚必须有效。
6. 列表、详情、二维码、订阅响应、链接与导出使用相同身份；新旧订单混合时各自保留正确格式。

本轮在本地测试数据上执行，不在生产订单页面下单，不修改线上商户名称，不推送、部署或触发共享环境流水线。

## 数据和环境

测试使用独立 SQLite 内存数据库和虚构账户。准备两家商户、管理员、新格式订阅、名称字段为空的旧订阅、原始订单及续费订单。旧订阅通过测试夹具构造，不读取生产客户数据。

名称数据包括 `GZXBL小北Mustafa`、16 个汉字、8 个 emoji、带 URL 和 HTML 特殊字符的合法短名，以及 null、空白、17 个汉字、9 个 emoji、控制字符和邮箱等非法输入。日期包含 UTC 与北京时间跨日边界。

UI 使用本机 Chrome、390px 和 1440px 视口及本地接口夹具。二维码占位图仅用于文字和几何布局检查；后端测试覆盖订阅链接和二维码接口响应，真实扫码解码与导入由客户端验收另行覆盖。

## 执行命令

在仓库根目录运行：

```powershell
php vendor/bin/phpunit tests/Feature/Distributor/DistributorSubscriptionNameTest.php --do-not-cache-result
php vendor/bin/phpunit --do-not-cache-result
node --test tests/JavaScript/*.test.js
node tests/Browser/distributor-subscription-name.cjs
php vendor/bin/phpstan analyse --no-progress --memory-limit=1G
composer audit --locked --no-interaction
git diff --check
```

浏览器命令需要 `NODE_PATH` 指向已安装的 Playwright 依赖；实际路径和版本记录在报告。PHPUnit 强制使用 testing、SQLite 内存库和隔离的缓存及队列设置。日志与 JUnit 使用各执行任务独立的临时目录，不记录真实 token、客户数据或生产环境配置。

## 实际客户端验收步骤

对三种客户端分别记录操作系统、客户端版本、测试实例版本和时间，再执行以下步骤：

1. 在测试实例保存一份旧订阅并记录显示名，升级测试实例后更新订阅，再续费及更新；显示名、链接、设备授权保持预期。
2. 新购普通混合名称、最长 16 汉字和最长 8 emoji 名称的订阅，分别通过链接及二维码导入；核对名称内容，无“订单号”前缀且未被错误截断。
3. 再次更新、关闭重开客户端、新订阅续费后更新，名称稳定且有效节点配置可用；商户改名不能重命名已有订阅。
4. 在隔离测试订阅上检验设备绑定和超限拒绝；短号替换 token 仍不能取得配置。保留脱敏截图和响应证据。

UI 因窄窗口显示省略号，应能在详情或编辑页核对完整名称；这与保存值被截断分开记录。不要为截图改动实际客户的订阅或设备。
